# 41. Only choices worth protecting get a record

- **Status:** Accepted
- **Date:** 2026-11-13

## Context

[24](0024-documentation-layout.md) gave every real choice a feature makes its own record, and forty records followed in
six days. Many protect nothing: they restate a convention, repeat a trade-off the feature's design already explains, or
describe API shape that the contract and `PublicAPI.*.txt` already pin down. Every accepted record is a constraint that
a change must be checked against, so minor records hide the important ones and slow every change down.

## Decision

A choice gets a record only if it passes all three tests in [`docs/README.md`](../README.md): it is costly to reverse,
a capable contributor might undo it without the record, and a real alternative lost for a reason specific to the case.
Other choices go to the feature's plan, `.editorconfig` or an analyzer, the contract, or the contract's out-of-scope
list.

[`README.md`](README.md) in this folder lists every record in one line, grouped by feature. It is generated by
`.github/scripts/build-decision-index.sh`, and CI fails when it is out of date.

Existing records stay as they are.

## Alternatives considered

- **A record for every choice, made easier to find with the index alone.** Rejected: the index speeds up finding a
  record, but every change is still checked against the same number of constraints.
- **Removing or merging the existing records that fall below the bar.** Rejected: accepted records aren't edited, and
  their reasons still hold.
- **A hand-maintained index.** Rejected: nothing would catch a missing or renamed record.

## Consequences

- New records are rarer, and each one matters to any change it covers.
- A feature's plan holds most of its trade-offs, so its pull request is the place to look for the reason behind a
  minor choice.
- Some existing records fall below the bar. They stay accepted and listed until a later record supersedes them.
- Adding a record, or changing a record's status, means running the index script.
